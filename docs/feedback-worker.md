# Private Atlas feedback worker (disabled by default)

This is a **narrow presentation/copy lane**, not an arbitrary UI-repair agent. No workflow, scheduler, live credentials, database, paid request, remote ref, PR, merge, or deployment is enabled by this code change. Local provider/GitHub HTTP servers in the tests are explicitly synthetic. Execution cost for this implementation: **UNPRICED**, not $0.

## Executable boundaries

- `runtime.ts worker` is a bounded private queue drain. It imports the backend's fixed `createFeedbackDatabase` factory, reads trusted source `main`, prepares disposable detached Git worktrees, and runs `runOne`. It refuses publisher credentials. Nothing invokes it automatically.
- `engine.ts` admits one immutable version-bound job via `WorkStore` (legacy public-only or the explicit new private-instruction mode), checks approval/version/fencing/kill control, runs trusted baseline checks, calls direct Anthropic Messages HTTP without tools, validates/applies a structured patch, runs candidate checks, checks the actual working tree again, then signs and durably hands off an Ed25519 receipt/bundle. No model-written command, CLI, package, test, or executable is run.
- `runtime.ts publisher` is a **separate process/identity**. It refuses provider/private-signing credentials, reads a persisted bundle and trusted source files, verifies signature/digests/policy first, and only then lazily loads its installation token. It never executes repository/model code or test commands (Git is used only to materialize/read a trusted base snapshot).
- `publisher.ts` uses the fixed `protocol/neuro-atlas` repository, `main`, `atlas-feedback/<feedback UUID>`, fixed commit identity/message, and `draft:true`. Public body contains exact approved task values as escaped JSON plus neutral validation text/digest. New private mode uses only the fixed server-owned generic task; no raw feedback, structural element metadata, legacy private comment, model rationale, logs, screenshot, or context dump is published. There is no merge, deployment, or general write endpoint.

Run either CLI with no flags/config to obtain `{"state":"disabled"}`. Enabling requires **both** `FEEDBACK_ENABLED=true` and the role-specific `FEEDBACK_WORKER_ENABLED=true` / `FEEDBACK_PUBLISHER_ENABLED=true`, plus all configuration and DB control limits. This document is not authorization to set those values.

## One-field private element mode

`SimpleFeedbackInput` is additive; legacy v1 inputs remain valid. Intake stores the raw `feedback` plus optional bounded structural `element` privately, projects public context without the element, and creates the exact fixed generic task in `src/lib/feedback/schema.ts` with `origin:'private-feedback-v1'`. Only that exact marker/title/summary/acceptance permits an explicit `{feedback,element?}` private instruction in the immutable job. Legacy private comments cannot enter this mode implicitly.

Acquisition validates exact payload keys, IDs/version/hash, public context and mode/instruction before dispatch; engine and model revalidate before inference/reservation. The instruction is bound to the immutable SQL job and current version/global/job fencing, not the public approval hash alone. That existing hash binds the generic public task (including its marker), existing publication policy and projected context; whole-request idempotency additionally binds the private note and element. Engine/model supply only allowlisted CSS sources and exact source hashes to the private model for this mode. Neither signed bundle nor publisher contains the private instruction. Publisher authority SQL explicitly excludes private job payloads.

**Private mode is CSS-only independently in engine and publisher.** Publisher revalidates the fixed marker and exact generic task/context plus signature/approval hash, then applies the CSS-only patch policy before loading credentials. A valid signed TSX patch is still rejected. Unknown/mixed markers, malformed instructions, selectors in public context or private bundle fields fail closed. Public PR title/body stay generic server-owned prose; raw feedback is never silently converted to public text.

For a simple follow-up, the full historical cumulative patch must already fit CSS-only scope **before baseline, inference or another reservation**. A prior v1 draft with approved TSX changes parks for human review rather than implicitly renewing its broader policy. CSS-only prior drafts can continue incrementally across legacy/simple modes, using original-main hashes, fresh receipts and the existing draft/branch. Prior private notes are never reconstructed from history or forwarded to later legacy requests. Partial-publication parking remains earlier than any inference in either mode.

No schema migration, services, live access or control changes accompany this mode. The existing immutable-job trigger protects the new JSON payload member. Review retention and column grants for private jobs before any separately approved activation.

## Deterministic edit policy

Only existing regular, non-executable Git blobs at these exact paths:

- CSS: `src/components/{landing,draft-chart-panel,draft-chart-plot,google-trends,performance-curves}.css`.
- TSX (**legacy expressly public-approved tasks only**): `src/components/site-nav.tsx`, `src/components/sections/velocity-tabs.tsx`.

CSS uses PostCSS. Existing node order, selector, property, at-rule, comments, and every byte outside approved declaration values stay identical. Only declaration values in existing rules (including existing `@media`) may change: bounded nonnegative spacing/radius (`0..96px`, `0..6rem`), font size (`12..48px`, `0.75..3rem`), unitless line-height (`1..2`), hex colors/transparent/currentColor, and a small enumerated set of alignment/weight/style values. No new rules/declarations, URL, variable/function, import, content, escape, or important changes.

For legacy public-approved tasks only, TypeScript AST identifies **existing `label: "..."` properties and literal `className="..."` attributes only**. All other bytes must be exact, so no new expression/import/href/URL/numeric/scientific-data edit. Labels are short alphabetic navigation/tab labels, not general scientific prose. Class changes are simple existing tokens plus a bounded spacing/radius utility grammar; template expressions and arbitrary Tailwind values are not editable. JSX text nodes are not an automatic copy lane.

Strict patch JSON is `{baseSha, files:[{path,beforeSha256,content}]}`. No extra keys; 1..5 files, at most 32 KiB serialized JSON, conservative 200 changed-line limit. Files must already exist in a clean exact-base checkout. New/deleted/renamed/binary/symlink/executable-mode/untracked/staged/stale changes park. Trusted `git apply` uses fixed argv, stdin data, no shell. Actual bytes, modes, HEAD, and changed file set are rechecked after candidate commands and again independently by the publisher.

## Durable integration

Apply backend-owned `db/feedback/001-feedback.sql`, then additive `002-worker.sql`, explicitly with a migration role. No runtime migration or memory fallback exists.

`ports.ts` defines `WorkStore`, `Capability`, `Bundle`, and signed receipt types; `publisher.ts` defines `PublicationStore`. `PgWorkStore` implements both against the backend's structural `QueryDatabase` interface. The CLI imports the actual backend factory from a fixed file URL after integration. No backend schema edits are required.

The singleton control lock serializes intake/worker operations; one global hard-deadline lease has monotonically increasing fencing. Missing/invalid owner, policy, finite budgets, tokens, turns, wall limit, or max attempts blocks dispatch. Job version/approval and job/global fencing are rechecked before inference, on a 100 ms cancellation heartbeat, and before each publishing write. Expired jobs park for review rather than silently spending again. Maximum two reservations/attempts is an upper bound, **not** a promise of an automatic retry: unknown provider outcomes, bad patches, baseline failures, stale bases, and human conflicts do not auto-retry.

`worker_reservations` records the worst-case USD/token reservation **atomically before HTTP**, bounded by charged+reserved job/day totals, turns and tokens. Known uncached usage settles idempotently; unknown usage/network outcomes retain the full reservation. Outstanding money carries across midnight and prevents a misleading daily reset. An operator must reconcile ambiguous spending; no automatic refund. The provider requests standard-only/global processing. Scalar cache counters accept absent/zero/null only because this fixed request never enables caching (neither top-level nor block cache_control); optional cache/tool/thinking detail objects accept absent/null or known zero counters. Nullable service-tier/geo/speed metadata is interpreted under the explicit standard-only/global request and absence of fast-mode opt-in. Required input_tokens/output_tokens must be actual bounded nonnegative integers, never null. Nonzero cached/tool/thinking consumption, premium modes, or unknown billing categories retain the reservation and fail closed rather than assuming a price. The contract is pinned by realistic positive nullable envelopes and negative billing cases against the [Messages API](https://platform.claude.com/docs/en/api/messages/create), [opt-in caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching) and [opt-in fast mode](https://platform.claude.com/docs/en/build-with-claude/fast-mode).

`worker_bundles` persists immutable private signed bundles; `jobs.candidate_ref` is their content digest, not a public URL. Publication rows bind receipt/version/digest, expected head and commit. Deterministic tree/commit requests plus branch/commit/tree/PR readback reconcile crashes after each HTTP write. Candidate trees are compared against **every base-tree leaf**, not just allowed blobs. Unexpected heads, closed/non-draft/cross-repo PRs, changed main, and stale versions stop. Explicit newly approved follow-ups reuse the same draft/branch, use a non-force fast-forward update from the recorded head, and update approved prose. Merged/live follow-ups remain the backend's human-review lane.

Follow-ups to `pr_ready` preserve cumulative approved draft changes. Acquisition locks the prior publication and binds its exact head/version/digests to the immutable completed bundle. The worker verifies historical signature, public approval, policy, checks and patch against the same trusted current-main snapshot before inference; historical expiry is not execution authority. It overlays verified prior changes for model input, validates incremental output against that draft, then validates/tests/signs a **new cumulative main-relative patch** with original main hashes. Baseline checks still run on clean main and candidate checks run on the full cumulative tree. Changed main, missing/mismatched history, or a signing-key mismatch parks before another model request. Human/unrecognized remote head changes still fail closed in the publisher. Cumulative edits must continue to fit the unchanged narrow patch policy and size/file limits; an empty cumulative diff parks rather than synthesizing a publication.

Any follow-up crossing `reserved`, `commit_created`, `ref_written` (or another non-`pr_ready` publication phase) is immediately `needs_human_review` with `partial_publication_followup`, a parked successor, and the old writer fenced. No inference or new spend is admitted, and the publication evidence is left untouched for operator reconciliation. Acquisition also parks impossible direct pending successors, so bypassing intake cannot admit an unpublishable model run. This intentionally does not auto-reconcile or discard even an apparently untouched reservation.

A separate per-job publisher claim prevents concurrent publishers. Claims renew for at most 30 seconds; takeover waits an additional full 15-second HTTP timeout after expiry so an old write cannot remain in flight. Receipt/global hard expiry still wins; a late crash can therefore require human review rather than automatic recovery. GitHub's externally initiated writes cannot be recalled once in flight; kill control stops every subsequent write. Production must supervise a single reviewed publisher service and never reuse one instance UUID across concurrent processes.

## Fixed checks and required host isolation

Checks are fixed `/usr/local/bin/npm --ignore-scripts test`, `... run typecheck`, `... run build`, in baseline and candidate. Existing reviewed package scripts are unchanged by the patch policy. Test/typecheck use `NODE_ENV=test`; build uses `NODE_ENV=production`. Each process group has a hard timeout, cancellation kill, bounded output, no shell, and an explicit minimal environment: no storage/provider/publishing/OAuth/Basic tokens, broker/home, or credential helpers. Only neutral hashes of command output are retained. Baseline failure blocks publication; there are no implicit baseline exceptions. The **whole job** wall clock includes baseline + inference + candidate checks + handoff, and is bounded by the earlier configured worker maximum/global lease (at most 600 seconds); per-command timeouts are at most 300 seconds. An overlong real Atlas suite can therefore leave insufficient time for candidate checks and must cancel/park, never claim success or extend its lease. The local complete suite took about 120 seconds once; slower hosts (e.g. four-minute baseline and candidate suites) need explicitly chosen limits that still fit this ceiling, or must remain disabled pending a separately reviewed limit change.

**Host isolation remains an activation prerequisite, not an OS sandbox claimed by these Node functions.** Run unprivileged processes with restricted filesystem/network, read-only reviewed dependencies, no host/broker sockets, only the needed DB columns, fixed executable paths and reviewed supervisor code. The runtime copies the trusted dependency tree into each disposable worktree (preserving internal package links without a root symlink or shared writable files); isolate/mount the candidate copy read-only. This avoids Next/Turbopack filesystem-root escapes and prevents candidate dependency writes from changing the trusted source tree. These tests exercise real subprocess stripping/timeouts, not a deployed container/network policy.

## Explicit runtime configuration (operator-only, no values checked in)

Shared role config: `FEEDBACK_DATABASE_URL` (different least-privilege role per process), `FEEDBACK_TRUSTED_REPOSITORY`, `FEEDBACK_DRAIN_MAX_JOBS` (1..10). Backend `control` must explicitly approve the owner, policy, job/day USD caps, token/turn/wall caps and max attempts (1..2).

Worker-only: `FEEDBACK_RECEIPT_PRIVATE_KEY` (Ed25519 PEM), `FEEDBACK_ANTHROPIC_API_KEY`, exact pinned `FEEDBACK_MODEL`, `FEEDBACK_MODEL_INPUT_USD_PER_MILLION`, `FEEDBACK_MODEL_OUTPUT_USD_PER_MILLION`, `FEEDBACK_MODEL_MAX_INPUT_TOKENS`, `FEEDBACK_MODEL_MAX_OUTPUT_TOKENS` (<=8192), `FEEDBACK_MODEL_MAX_BODY_BYTES` (<=131072), `FEEDBACK_MODEL_MAX_RESPONSE_BYTES` (<=262144), `FEEDBACK_MODEL_TIMEOUT_MS` (<=120000), `FEEDBACK_WORKER_MAX_WALL_MS` (<=600000). Prices must be operator-verified for that exact uncached model/billing mode; no default price/model exists. UTF-8 bytes plus a protocol allowance provide a conservative input-token bound before reserving.

Publisher-only: `FEEDBACK_RECEIPT_PUBLIC_KEY` (Ed25519 PEM) and broker-injected short-lived `FEEDBACK_GITHUB_INSTALLATION_TOKEN`, contents+pull_requests for this repo only. Never pass this environment to the worker/check subprocess. The provider and GitHub production origins are fixed; loopback HTTP injection is test-only and denied under production/Vercel.

The migrations create no accounts/grants. Before activation, provision reviewed column-limited DB roles: intake owns private input/auth; worker reads immutable job payload/control (including the explicit simple-mode private instruction) and mutates its jobs/accounting/bundles; publisher reads only public signed bundles/control and updates publication/claim/status fields. Worker acquisition/current checks use `j.*`, never `feedback.input_private`. Publisher authority checks project only `j.id,feedback_id,input_version,approval_hash,state,fencing_token,base_sha,lease_until,attempt,reserved_cost,charged_cost` plus current safe feedback version/approval/owner/state; other publisher job reads use only id/base/candidate/state fields. Publisher must have **no SELECT on jobs.payload or feedback.input_private**. Existing roles/grants must be reviewed for this changed private-job boundary before activation. Separate credentials alone do not implement those deployment grants.

Approval-hash compatibility (absent, populated, and explicitly undefined optional context fields) is checked against the actual backend `publicApprovalHash` export, not a fabricated substitute. A worker-only verification can supply the backend migration/intake module through the two explicit test-only paths above.

Tests use real temporary Git repositories, actual PostCSS/TypeScript parsing, real npm child processes, disk-backed PostgreSQL-WASM/PGlite transactions/restarts using both real migrations, synthetic Anthropic/GitHub HTTP fixtures, signed immutable SQL outbox, budgets/unknown spend/fences, kill during inference, follow-up reuse, and crash-boundary reconciliation. Fixture success is **not** a real provider/App/preview acceptance run.

Before any live flow: owner approval for spending/activation; private PostgreSQL + grants/backups/retention; isolated worker/publisher services and egress policy; provider pricing/billing verification; broker-held App credentials and exact scopes; signing-key custody; emergency-stop drill; independent security review; real owner OAuth/intake → one actual draft PR → exact-SHA preview verification. No preview, merge, or live status is synthesized by this worker.
